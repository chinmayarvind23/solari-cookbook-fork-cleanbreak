# CleanBreak Implementation Status

- Current milestone: Milestone 4 — human approval and crash-safe cancellation commit.
- Approval implementation: `/demo` renders an exact financial confirmation for service, domain, plan, recurring price, annual savings, current status, final action, visible terms, cancellation fee, access end, final screenshot, and observation time. The primary action is **Approve cancellation** and the secondary action is **Abort**. Nonzero or unknown fees have no approval control or override.
- Fingerprint implementation: every proposed action persists a canonical `ApprovalSnapshot` and deterministic SHA-256 fingerprint. The client submits only job ID, intent, and fingerprint; the server reloads authoritative job/proposal/approval data and requires an exact match, eligible final-action policy classification, `AWAITING_APPROVAL`, and a zero fee.
- Commit idempotency: approval and commit records are durable SQLite rows. `BEGIN IMMEDIATE` plus a conditional `AWAITING_APPROVAL → COMMITTING` update and a unique commit attempt per job allow one caller to arm. A durable `final_action_attempted_at` marker is stored before Playwright can click. A second/concurrent request returns existing state. `destructive_clicks_executed` is constrained to at most one and `automatic_destructive_retries` is constrained to zero.
- Fresh execution boundary: the commit launches a new recorded Solari session using the navigation job's saved profile, returns deterministically to the approved URL, creates a new observation and target map, and compares material terms. It never reuses the navigation observation target ID. Changed terms replace the proposal, supersede the approval, and return to `AWAITING_APPROVAL`. An already-canceled page executes no final click and moves toward verification.
- Crash recovery: armed attempts always move to `VERIFYING`, never `VERIFIED`. Recovery of a `COMMITTING` job with an attempt marker records an unknown outcome when needed and prohibits another click. Four deterministic hooks cover before arm, after arm/pre-click, after dispatch, and after click return/pre-transition.
